# WhatsApp and Telegram Integration Notes

Channel adapters should be thin. Their responsibility is to receive provider webhooks, verify signatures where available, resolve the correct tenant/client, and pass normalized messages to the core orchestrator.

## Normalized Inbound Message

```json
{
  "tenantId": "tenant-uuid",
  "channel": "whatsapp",
  "channelUserId": "+905555555555",
  "providerMessageId": "wamid.xxx",
  "body": "Bugün kahvaltıda ne yiyebilirim?",
  "receivedAt": "2026-05-22T12:00:00.000Z"
}
```

## Adapter Responsibilities

- Map `channel + channelUserId` to exactly one active client.
- Reject or quarantine ambiguous mappings.
- Load dietitian, client, conversation, selected persona, AI activation state, AI mode, voice profile, and memory.
- Call `handleInboundMessage`.
- Persist the inbound message, risk assessment, AI decision, outbound message, message origin, and audit event.
- Send outbound messages only when the returned action is `sent`.
- Show `draft_for_approval` and `handoff` actions in the dietitian dashboard.

## Required Dashboard Controls

- Client-level persona selector
- Client-level AI activation toggle: `active` or `passive`
- Optional activation window controls
- Client-level AI mode selector: `autopilot`, `copilot`, `manual`, `paused`
- Handoff case queue
- Case resolve button
- Pause/resume AI for a client
- Conversation timeline with AI decisions and quality guard issues
- Message origin labels: client, AI, dietitian, system

## Failure Behavior

The default behavior is fail-closed:

- Unknown client: do not generate.
- Missing profile: do not auto-send.
- Yellow or red risk: do not auto-send.
- Quality guard failure: do not auto-send.
- Provider send failure: record decision and expose retry to operator.
- Passive AI state: do not generate, draft, or auto-send.

## Message Origin Rules

- Client inbound messages are stored as `client_inbound`.
- AI auto-sent messages are stored as `ai_generated`.
- Dietitian-written messages are stored as `dietitian_manual`.
- Dietitian-approved AI drafts should retain both fields: generated by AI and approved by dietitian.
- Imported history with uncertain author is stored as `imported_unknown` and is excluded from training/evaluation datasets until reviewed.
